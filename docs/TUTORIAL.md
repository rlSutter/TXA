# The TXA Tutorial: The Ferry House

Generated by `tools/gendocs.py`; the programs are `samples/tutorial/ferry1.txa` to `ferry5.txa`, quoted here as they are, and `tests/tutorial_test.py` compiles and plays every one. The game: a river, a locked ferry house, and a ferryman who wants a penny.

A TXA program is plain text (DIS/VAR 80 on the TI, any text file on a PC). Compile it on the TI with the TXA Workbench (P, then C; T to play it), or on a PC:

```
python3 tools/txa_game.py samples/tutorial/ferry5.txa --prefix FERRY --out build/ferry
```

which writes the game's files and a disk image (`--cart` makes a FinalGROM cartridge instead). The *Authoring Language Reference* has the language; the *Standard Library Reference* has every attribute, property, verb and routine used here.

## Chapter 1: a room

Every game starts with the library, and supplies `Initialise`, which says where the player begins. A room has a name (shown in bold), a description, and `light` so the player can see.

```
! ferry1.txa - "The Ferry House", the tutorial's game: chapter 1.
INCLUDE "DSK1.STDLIB"

ROOM Landing "Landing Stage"
  DESC "Weathered planks stand out over a slow brown river. A path climbs north to the ferry house."
  HAS light
END

ROUTINE Initialise
  location = Landing
  TitlePage("THE FERRY HOUSE", "A TXA tutorial", "A river, a ferryman, and a penny for the crossing.")
END
```

`TitlePage` shows a title page before the game starts. That is a whole game already: LOOK, INVENTORY, SAVE, UNDO and the rest all work, because they are the library's.

## Chapter 2: places and things

A second room, joined by exits: `N Porch` on the landing, `S Landing` on the porch. Exits are properties, so a game can change them while it runs.

```
ROOM Porch "Porch"
  DESC "A sagging porch. The ferry house's door is east; the landing stage is back down the path to the south."
  HAS light
  S Landing
END
```

Objects say where they start (`IN`), the words that name them (`NAME`), and what EXAMINE says (`DESC`). The bench is `static` (it cannot be taken) and a `supporter` (things go on it); the coin starts on it. The river is `scenery`: mentioned in the room's description, so not listed again.

```
OBJECT Bench "bench" IN Landing
  NAME "bench" "wooden"
  HAS static supporter
  DESC "A bench for waiting passengers, polished by years of them."
END
OBJECT Coin "copper coin" IN Bench
  NAME "copper" "coin" "penny"
  DESC "A worn copper penny: the ferry's fare."
END
OBJECT River "river" IN Landing
  NAME "river" "water"
  HAS scenery
  DESC "Too wide and too deep to wade."
END
```

## Chapter 3: a locked door, and a new verb

A door is an object with `door`, in the exits of the rooms on both sides (`FOUND_IN` puts one object in several rooms), leading to its `DOOR_TO`. It starts `locked`, and its `WITH_KEY` unlocks it.

```
OBJECT FrontDoor "front door"
  NAME "front" "door"
  HAS door openable lockable locked static scenery
  WITH_KEY Key
  DOOR_TO Porch Parlour
  FOUND_IN Porch Parlour
END
```

The key is hidden. It starts nowhere (no `IN`), and a `BEFORE` rule on the doormat moves it into the room when the mat is lifted, pulled, turned or searched. The rule returns TRUE, so the usual action (which would refuse: the mat is static) does not happen. `general` is an attribute the game may use for anything: here, that the key has been found.

```
OBJECT Mat "doormat" IN Porch
  NAME "mat" "doormat"
  HAS static
  INITIAL "A doormat lies in front of the door, curled at one corner."
  DESC "Its curled corner hides something."
  BEFORE
    Take, Pull, Turn, Search:
      IF Key HAS general
        PRINT "Nothing else under there."
      ELSE
        GIVE Key general
        MOVE Key TO location
        PRINT "You lift the corner. Underneath lies an iron key."
      END
      RETURN TRUE
  END
END
```

LIFT is not one of the library's verbs, so the game adds it, as another way to PULL:

```
VERB "lift" "raise"
  noun -> Pull
END
```

The tin box is a `container` that is `openable`, with the ticket inside.

```
OBJECT Box "tin box" IN Parlour
  NAME "tin" "box"
  HAS container openable
  DESC "A tin box with a stiff lid."
END
OBJECT Ticket "ferry ticket" IN Box
  NAME "ferry" "ticket"
  DESC "A stub stamped OUTWARD."
END
```

## Chapter 4: a character

The ferryman is `animate`: ASK, TELL and GIVE go to his `LIFE`, a case per action, with `noun` (what is given) set. Giving the coin moves it to him and the player across the river (`GoTo`), to a room no exit reaches: the map changes by what happens. GIVE takes the coin first if the player has not ("(first taking the copper coin)").

```
OBJECT Ferryman "ferryman" IN Landing
  NAME "ferryman" "old" "man"
  HAS animate male
  INITIAL "The ferryman leans on his pole, waiting for a fare."
  DESC "Patient as the river."
  LIFE
    Ask, Tell:
      IF WordIs('river') OR WordIs('ferry')
        PRINT "~One penny across. No penny, no crossing.~"
      ELSE
        PRINT "He shrugs."
      END
      RETURN TRUE
    Give:
      IF noun = Coin
        MOVE Coin TO self
        PRINT "He bites the coin, nods, and poles you across."
        GoTo(FarBank)
      ELSE
        PRINT "~That's not the fare.~"
      END
      RETURN TRUE
  END
END
```

ASK and TELL leave the topic's words where the parser found them; a small routine asks whether a word was among them:

```
! was word w in the topic of ASK or TELL?  (topicwn, topiclen: the parser's)
ROUTINE WordIs w
  LOCAL k
  WHILE k < topiclen
    IF WordAt(topicwn + k) = w
      RETURN TRUE
    END
    k = k + 1
  END
  RETURN FALSE
END
```

## Chapter 5: time, a score, and an ending

A daemon runs every turn once started. The bell counts down a global and rings every fourth turn, but only where it can be heard:

```
OBJECT Bell "bell"
  NAME "bell"
  DAEMON
    bell_turns = bell_turns - 1
    IF bell_turns <= 0
      bell_turns = 4
      IF location = Landing OR location = Porch
        PRINT "Across the water, a bell rings for the ferry."
      END
    END
  END
END
```

`Initialise` starts it and sets the most points there are; the ferryman's GIVE adds 5 to `score` and sets `deadflag = 2`, which ends the game as won.

```
ROUTINE Initialise
  location = Landing
  max_score = 5
  StartDaemon(Bell)
  TitlePage("THE FERRY HOUSE", "A TXA tutorial", "A river, a ferryman, and a penny for the crossing.")
END
```

## Where next

- **Pictures and music**: declare them (`PICTURE CavePic "CAVE"`, `MUSIC HarbourTune "HARBOUR"`), give rooms a `PIC` and a `TUNE`, and the library shows and plays them; pictures come from PNGs or TI Artist files, music from TXA music notation (`docs/MUSIC.md`) or MIDI. *Lamplight* (`samples/lamplight.txa`) uses all of it.
- **Testing**: on the TI, T test-plays with TREE, GOTO, PURLOIN and the rest; RECORD and REPLAY rerun a walkthrough after each change. On a PC, the reference VM plays a list of commands, as `tests/tutorial_test.py` does.
- **Size**: S shows how much room is left; the dynamic area (16K) fills first.
